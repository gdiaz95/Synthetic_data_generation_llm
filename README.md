# Synthetic Data Generation (LLM)

> Enterprise repository: [github.com/safeinsights/synthetic-data-generation-llm](https://github.com/safeinsights/synthetic-data-generation-llm)

Generate synthetic tabular datasets whose structured columns come from a
tabular synthesizer (NPGC) and whose free-text columns (e.g. job
descriptions, reviews) are generated by an LLM conditioned on the nearest
real-data neighbors of each synthetic row. Includes tooling to evaluate
fidelity, privacy, and statistical significance of the results.

For a full field-by-field breakdown of every config option, see
[docs_config_reference.md](docs_config_reference.md). This README only
covers how to run things.

## Setup

- Python 3.10–3.13, [Poetry](https://python-poetry.org/).
- Install dependencies:
  ```bash
  poetry install
  ```
- Create a `.env` file in the repo root with whichever keys your provider needs:
  ```
  GEMINI_API_KEY=...
  OPENAI_API_KEY=...
  HUGGINGFACE_HUB_TOKEN=...
  ```

## Directory map

| Path | Contents |
|---|---|
| `configs/` | YAML configs: `tabular.yml`, `llm_generation.yml`, `prompts.yml`, `metrics.yml` |
| `data/potential/`, `data/raw/` | Raw source CSVs before / after preprocessing |
| `data/processed/` | Generated synthetic CSVs |
| `data/small/` | Small hand-curated datasets (e.g. UCI Adult + augmented text) |
| `.metadata/{dataset}/metadata.json` | Per-dataset free-text columns / target column, created interactively on first run |
| `pre_processing/` | Per-dataset raw → clean CSV scripts |
| `source/pipelines/` | The runnable pipeline scripts (see below) |
| `experiments/` | Batch shell scripts that loop pipelines over many datasets |
| `reports/`, `reports/membership/`, `reports/llm_metrics/` | JSON metric outputs |
| `logs/` | Per-run generation logs |

## Workflow

Run these in order for a new dataset. All commands are run from the repo root unless noted.

### 1. Preprocess a raw dataset

```bash
cd pre_processing && python process_all.py
```

Reads `data/potential/*.csv`, cleans columns per-dataset, writes `data/raw/*.csv`.
Safe to re-run — it skips any dataset whose `data/raw/{name}.csv` already exists.
To process a single dataset instead, run its script directly, e.g. `python Airbnb.py`.

### 2. Generate synthetic data

**Main pipeline** (tabular synthesis + KNN-conditioned LLM text generation):

```bash
python -m source.pipelines.run_full --dataset-name <name> --model <model> --provider auto
```

- On the **first** run for a dataset with no `.metadata/{name}/metadata.json`, this
  prompts interactively (needs a TTY) to pick free-text columns, a target column,
  and distance weights, then saves that choice for future runs.
- Add `--yes` to skip the billing confirmation prompt for paid API calls.
- Add `--k-neighbors 0` to run the no-context ablation (ignores neighbor examples).
- Local models: pass `--provider local --gpu-index <idx> --gpu-memory-utilization 0.8`.
- Output: `data/processed/{name}_{model}.csv` plus a run log in `logs/`.

**GReaT baseline** (fine-tune a local Qwen model on serialized rows instead):

```bash
python source/pipelines/run_great.py --dataset-name <name> --gpu-index <idx>
```

Output: `data/processed/{name}_{model}_great.csv`.

### 3. Evaluate the synthetic data

```bash
# Structured-column quality, SDV score, free-text distribution metrics, optional TSTR + LLM judge
python -m source.pipelines.run_structured_metrics --dataset-name <name> --generator-model <model>

# BERTScore / MAUVE / NNDR privacy proxy for free-text columns
python source/pipelines/run_llm_text_metrics.py --dataset-name <name> --generator-model <model>

# Distance-based membership-inference privacy check
python -m source.pipelines.run_membership --dataset-name <name> --generator-model <model>
```

Each reads `real_data_path`/`synthetic_data_path` from `configs/metrics.yml`
(templated with `{dataset_name}`/`{generator_model}`), so the synthetic CSV from
step 2 must already exist. Reports land in `reports/`, `reports/llm_metrics/`,
and `reports/membership/` respectively. Add `--yes` to skip the LLM-judge
billing prompt.

### 4. Aggregate significance across all reports

```bash
python source/pipelines/run_significance_tests.py
```

Purely offline — scans every `reports/*_structured_metrics.json` produced in
step 3 and writes `reports/significance_tests.json` (binomial/Wilson CIs, sign
tests, cross-judge z-tests, k=0-vs-k=5 ablation comparison).

### Batch scripts

Loop the evaluation steps over the full set of datasets/models already encoded in each script:

```bash
bash experiments/run_membership_all.sh
bash experiments/run_text_metrics_all.sh
```

## Using your own dataset

The pipeline has no hardcoded dataset list or required column names — any CSV
works. Pick `<name>` (letters/numbers/`_`/`-`), then follow these steps.

### 1. Get a clean CSV to `data/raw/<name>.csv`

Two options:

- **Already clean?** Just copy/save it directly to `data/raw/<name>.csv` and
  skip preprocessing entirely.
- **Needs cleaning** (dropping ID columns, fixing encoding, etc.)? Add a new
  `pre_processing/<name>.py` following the existing pattern, e.g.
  [`pre_processing/Airbnb.py`](pre_processing/Airbnb.py):
  ```python
  from pathlib import Path
  import pandas as pd
  from _common import POTENTIAL_DIR, RAW_DIR, run_preprocessing

  INPUT_FILE = POTENTIAL_DIR / "<name>.csv"   # put the raw file here first
  OUTPUT_FILE = RAW_DIR / "<name>.csv"

  def preprocess_columns(df: pd.DataFrame) -> pd.DataFrame:
      # drop/clean columns here
      return df

  def main() -> Path:
      return run_preprocessing("<name>", INPUT_FILE, OUTPUT_FILE, preprocess_columns)

  if __name__ == "__main__":
      main()
  ```
  Then either run it directly (`cd pre_processing && python <name>.py`) or add
  `("<name>", <name>.main)` to the `PROCESSORS` list in
  [`pre_processing/process_all.py`](pre_processing/process_all.py) so it's
  included in the batch run.

### 2. Point the tabular config at it (optional)

`--dataset-name <name>` on the command line is enough — it's substituted into
the `data/raw/{dataset_name}.csv` / `data/processed/{dataset_name}.csv`
templates in `configs/tabular.yml` automatically. Only edit
`configs/tabular.yml`'s `dataset_name:` field if you want `<name>` to be the
default when no `--dataset-name` flag is passed.

### 3. First generation run — answer the interactive prompts

```bash
python -m source.pipelines.run_full --dataset-name <name> --model <model>
```

Since `.metadata/<name>/metadata.json` doesn't exist yet, this drops into an
interactive setup (needs a real terminal, not a piped/non-interactive shell).
It will ask, in order:

1. **Dataset name for metadata storage** — press Enter to accept `<name>`.
2. **Free-text columns** — it auto-detects likely free-text columns (high
   unique-value ratio + averaging 3+ words) and shows them as a default;
   press Enter to accept, or type your own comma-separated column names.
3. **Max words for LLM generation** — shown alongside word-count stats for
   each chosen free-text column; press Enter to accept the suggested default.
4. **Custom feature weights** — `y/N`; only needed if some structured columns
   should matter more/less in the KNN neighbor search.
5. **Optional target column** — for downstream TSTR metrics; press Enter to skip.

Your answers are saved to `.metadata/<name>/metadata.json` so every later run
(and every evaluation step) reuses them without prompting again.

### 4. Continue with the normal workflow

From here on, `<name>` behaves exactly like any of the existing datasets —
continue with steps 2–4 in [Workflow](#workflow) above (evaluate, then
aggregate significance), always passing the same `--dataset-name <name>`.

## Config files at a glance

| File | Purpose |
|---|---|
| `configs/tabular.yml` | Input/output CSV paths, KNN neighbor count, tabular synthesizer params |
| `configs/llm_generation.yml` | Model/provider selection, sampling params, local vLLM settings, retry behavior |
| `configs/prompts.yml` | Prompt templates for free-text generation |
| `configs/metrics.yml` | Evaluation data paths, LLM-judge settings, TSTR weighting |

See [docs_config_reference.md](docs_config_reference.md) for every field, its
effect, and current default.

## Notes

- `--provider auto` infers Gemini vs OpenAI vs local from the `--model`/`model` string.
- Dataset/model names get substituted into config path templates like
  `data/processed/{dataset_name}_{model}.csv` — keep `--dataset-name` consistent
  across generation and evaluation steps for a given dataset.
- Each pipeline run's console output is also written to `logs/{run}.log`.
